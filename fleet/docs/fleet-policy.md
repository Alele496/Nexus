# 舰队架构原则

## 跨项目架构原则

### 1. 分层反脆弱

每层有自己的生命周期，不互相阻塞：
- **旗舰项目**：主力开发，完整 Agent 团队 + health check
- **模板项目**：通用模板，偶尔同步改进
- **卫星项目**：独立项目，有自己的 `.grok/` Agent 配置

### 2. 项目分级

| 级别 | 说明 | 健康检查频率 | 例子 |
|------|------|-------------|------|
| **旗舰** | 主力开发项目 | 每 4h quick + 每日 full | Agent-SYS |
| **模板** | 通用模板仓库 | 每日 quick | agent-crew |
| **卫星** | 独立项目 | 每日 quick | 各业务项目 |

### 3. 命名和路径约定

- 项目目录名使用 kebab-case
- AGENTS.md 在每个项目的根目录
- `.grok/` 目录包含项目专属 Agent 配置
- `project-memory.md` 记录项目记忆和决策

### 4. 跨项目影响追踪

当模板项目（如 agent-crew）的 Agent 定义发生变更时：
1. 在 cross_project_impact 中记录
2. 评估对下游消费者项目的影响
3. 通知下游项目手动同步或更新

### 5. 开发哲学

- **Agent 配置即代码**：`.grok/` 目录受版本控制
- **本地优先**：每个开发者有自己的 grok session，不共享
- **按需协作**：通过 fleet-registry 了解其他项目，但不强制耦合
- **模板驱动**：新项目从 Agent-SYS 复制 `.grok/` 模板启动
